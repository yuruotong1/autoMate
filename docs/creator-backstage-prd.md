# 创作者后厨（Creator Backstage）需求文档

> 版本：v0.1（探索稿）
> 日期：2026-04-30
> 状态：方向探讨中，未立项

---

## 1. 背景

### 1.1 作者自述

我是一名喜欢创作的开发者，日常会做两类内容：
- 录代码 / 录视频，发布到视频平台
- 写技术见解、文章，发布到图文平台

我目前手头的工具栈：

| 工具 | 解决的问题 |
| --- | --- |
| 扣子 | 日常文件、信息归集、日程、备忘录 |
| Claude（chat） | 大部分编程、文件处理、内容生成 |
| ChatGPT / Kimi | 备用对话 |
| Cursor | 主力写代码 |
| ImCode | 便宜场景下的简单代码处理 |

在产品工具层面，我目前**没有明确的新需求**——直到我把视角切到"创作者"身份。

### 1.2 真实痛点

> "我想把精力放在核心技术与内容本身，不想做营销包装；
> 但没有包装的内容就没有流量，AI 代写的内容一眼假、且会被平台降流。"

具体表现：
1. **流量焦虑**：好流量依赖三件事——大量包装、及时性、稀缺性。这三件事都在偷走我做内容本身的时间。
2. **AI 代写失败**：我尝试过用各级大模型直接写文章 / 写流帖，结果是：
   - 文风一眼 AI，读者直接划走
   - 平台检测器降权，自然流量被压
   - 即使是当前最强模型也无法解决
3. **根本矛盾**：我擅长的是"做"（写代码、调 bug、做项目），但流量奖励的是"包装"（选题、结构、节奏、人设）。

### 1.3 为什么现有 AI 工具解决不了

| 现有方案 | 失败原因 |
| --- | --- |
| ChatGPT / Claude 直接生成文章 | 凭空创作，信息密度均匀，缺少个人视角与跳跃感，AI 味重 |
| Notion AI / 各类 AI 写作工具 | 定位是"代笔"，本质上仍在让 AI 替人写 |
| 选题工具（如新榜） | 只给热榜，不结合个人素材库，无法回答"我这周的素材里哪个能蹭到这个热点" |

**结论**：问题不在模型够不够强，而在产品形态错了——市场上都在做"AI 替你写"，没人做"AI 帮你把已有素材包装成爆款结构"。

## 2. 产品定位

### 2.1 一句话定位

> **创作者后厨**：让创作者只关注核心技术与内容，把"选题—包装—节奏"交给 AI 编辑，而不是 AI 代笔。

### 2.2 核心理念

- ❌ 不做：输入主题 → AI 凭空生成完整文章
- ✅ 要做：输入"原始素材（commit / 笔记 / 视频草稿 / 吐槽）" → AI 输出"爆款结构骨架 + 选题建议 + 风格校准" → 由作者填血肉

差异化的根本在于：**保留作者的视角与稀缺性，只把可工业化的"包装"交给 AI。**

### 2.3 目标用户

- **第一用户**：作者本人（必须自己每天用，否则项目立刻停）
- **后续用户画像**：技术型 / 专业型创作者——有真东西可讲，但缺乏运营精力的人
  - 程序员 / 独立开发者
  - 设计师 / 产品经理
  - 学者 / 行业从业者

显式排除：纯营销号、搬运号——他们要的是"代笔"，不是这个产品。

## 3. 核心功能

### 3.1 模块 A：素材池（Material Pool）

**目标**：自动收集作者的"创作原料"，无需手动整理。

**数据源**：
- Git commit 记录（包含 diff 摘要）
- Cursor / Claude 聊天记录
- 本地随手笔记（Markdown / 扣子笔记）
- 视频草稿、剪映工程文件
- 浏览器中收藏 / 高亮的网页

**关键能力**：
- 自动抓取与索引（这一步可以复用 autoMate 现有的本地自动化能力）
- 按主题、时间、技术栈打标签
- 支持自然语言检索："我上周调过的那个 React hook bug"

### 3.2 模块 B：选题雷达（Topic Radar）

**目标**：把"热点"和"我的素材"做交叉，找到**及时性 × 稀缺性**的命中点。

**关键能力**：
- 抓取目标平台热榜（小红书 / B站 / 知乎 / 掘金 / X 等）
- 与素材池做语义匹配
- 输出形如：
  > "你 3 天前调过的 `useEffect` 死循环 bug，正好对应今天 X 话题在涨。
  > 建议切入点：'90% 的人不知道的 useEffect 陷阱'，预计窗口期 48 小时。"

### 3.3 模块 C：结构化包装（Structure Packaging）

**目标**：不生成正文，而是生成"骨架"。

**输出形态**（举例）：

```
[钩子句位置]：用一个反直觉的事实开篇，建议 15 字以内
[第一段]：抛出读者的痛点（你的素材里有这段：xxx，可以直接用）
[节奏断点]：这里读者会失去耐心，建议插入一个代码片段或截图
[互动钩子]：在第 X 段末尾抛一个问题，让读者评论
[结尾]：留白式收尾，不要总结
```

**为什么这是关键差异化**：
- 解决了"AI 味"问题——文字仍由作者写
- 把"包装"这件可工业化的事交给 AI
- 作者的稀缺视角被 100% 保留

### 3.4 模块 D：风格防伪（Anti-AI Style）

**目标**：在作者确实需要 AI 协助补段落时，让输出尽量像作者本人。

**关键能力**：
- 用作者过去的高赞内容做 few-shot 样本
- 注入"人类写作信号"：突兀的口语、短句跳跃、个人化吐槽
- 提供"AI 味检测分数"，低于阈值才允许发布

## 4. 与 autoMate 的关系

这是一个需要回答的关键问题。

### 4.1 选项 A：基于 autoMate 改造

**优势**：
- autoMate 已具备"AI 操控本地软件"的能力，对素材池抓取（Cursor 历史、本地视频、剪映工程）天然适配
- 不浪费已有代码

**风险**：
- 用户心智混乱——RPA 工具突然变成创作平台
- 历史代码可能成为包袱

### 4.2 选项 B：新开仓库，autoMate 归档或维持现状

**优势**：
- 定位清晰，从零设计
- autoMate 可以单独作为"本地素材抓取层"被这个新项目调用

**风险**：
- 需要重新搭基础设施

### 4.3 倾向

**倾向选项 B**，但把 autoMate 作为底层依赖之一。
理由：产品定位差异巨大，强行合并会让两边都不清晰。

## 5. 验证路径（关键）

**在写任何代码之前**，必须先做手动验证。

### 5.1 第一步：纯手动跑流程（1 周）

- 不写工具，全部手动执行模块 A→B→C 的流程
- 按这个流程发 5 篇文章 / 5 个视频
- 对照过去自然发布的内容，看流量是否提升

**通过标准**：至少 2/5 内容流量明显高于历史均值。

### 5.2 第二步：单点工具化（2 周）

如果第一步通过，先做模块 C（结构化包装）——这是差异化最大、最容易验证的点。

**通过标准**：自己每天会用，且确实节省了创作时间。

## 6. 风险与开放问题

### 6.1 风险

| 风险 | 说明 |
| --- | --- |
| 平台反爬 | 抓取热榜、平台数据可能违反 ToS，需评估 |
| 仍是伪需求 | 作者本人都未必会持续使用——必须以第 5 节的验证为前置 |
| 模块 C 可能仍然 AI 味重 | 即使只生成骨架，模板化也会暴露——需要在验证阶段重点测 |
| 用户数量天花板 | 技术型创作者是小众市场，商业化路径需另议 |

### 6.2 开放问题

1. 是否要支持多平台？还是先聚焦一个平台（比如小红书或掘金）？
2. 风格防伪能否真正过 AI 检测？需要做技术预研。
3. 选题雷达的"及时性窗口"如何量化？
4. 是否需要做一个"发布后效果回流"的闭环（流量、互动数据回流到选题雷达）？

## 7. 下一步行动

1. **作者自查**：选一篇过去"内容好但流量崩"的文章，分析是包装问题、选题问题、还是平台权重问题——这决定模块优先级。
2. **手动验证**：按第 5.1 节执行 1 周。
3. **再决策**：基于真实数据决定是否立项、立在哪个仓库。
